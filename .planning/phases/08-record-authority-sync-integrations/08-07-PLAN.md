`plans.ts`'s `fetchPlanRow` is a private (non-exported) function scoped to that module. Two implementation options — pick whichever keeps the change smallest and avoids introducing any cross-module import cycle (confirm first: does `plans.ts` import anything from `document-adapter.ts`, directly or transitively? It currently imports `revalidateDocumentLinkPermission` from this very file — so `plans.ts` → `document-adapter.ts` already exists. A reverse import `document-adapter.ts` → `plans.ts` would create a TRUE two-file cycle, which Node's ESM loader CAN handle for function-level imports but is worth avoiding on code-health grounds given no such two-file cycle exists anywhere else in this codebase today):

**Preferred approach — self-contained check in document-adapter.ts (no new cross-module import, no cycle risk):** Add a small private helper in `document-adapter.ts` itself that mirrors `fetchPlanRow`'s exact query shape (same `plans.jurisdiction_id = ANY($2)` scoping clause), e.g.:
```ts
async function planIsInScope(planId: string, jurisdictionScope: string[]): Promise<boolean> {
  const rows = await query<{ id: string }>(
    `SELECT id FROM plans WHERE id = $1 AND jurisdiction_id = ANY($2)`,
    [planId, jurisdictionScope],
  );
  return rows.length > 0;
}
```
This is a deliberately minimal existence+scope check (not a full `fetchPlanRow`-style join) since `linkDocument()` only needs a boolean, not the full plan row.

Then in `linkDocument()`:
```ts
export async function linkDocument(
  userId: string,
  externalDocId: string,
  planId?: string,
  jurisdictionScope?: string[],
): Promise<{ id: string }> {
  const accessSet = resolveUserAccessSet(userId);
  if (!accessSet.includes(externalDocId)) {
    throw new Error('IMPORT_PERMISSION_DENIED');
  }

  if (planId) {
    const inScope = jurisdictionScope ? await planIsInScope(planId, jurisdictionScope) : false;
    if (!inScope) {
      throw new Error('PLAN_NOT_FOUND');
    }
  }

  // ... existing DOCUMENT_CATALOG lookup + INSERT unchanged ...
}
```
`jurisdictionScope` is a NEW optional 4th parameter — optional so the seed script's existing `linkDocument(plannerUser.id, 'DOC-SOP-002', uatUnlinkedPlan.id)` 3-arg call (no jurisdiction scope available in that seed context) would silently throw `PLAN_NOT_FOUND` since `jurisdictionScope` would be `undefined`. Fix the seed call site too: `backend/scripts/seed.ts`'s call passes `plannerUser.id, 'DOC-SOP-002', uatUnlinkedPlan.id` — add the planner's own jurisdiction scope as a 4th argument (the seed script already has `jurisdiction.id` in scope at that point in the file — pass `[jurisdiction.id]`). Grep `backend/scripts/seed.ts` for the exact call site and variable names before editing; do not assume the variable name without confirming it against the file's actual content.

Update the route handler to pass `req.epmpUser!.jurisdiction_scope` through:
```ts
app.post<{ Params: { id: string }; Body: { plan_id?: string } }>(
  '/api/v1/integrations/documents/:id/link',
  { preHandler: requirePermission('plans', 'edit') },
  async (req, reply) => {
    try {
      const result = await linkDocument(
        req.epmpUser!.id,
        req.params.id,
        req.body?.plan_id,
        req.epmpUser!.jurisdiction_scope,
      );
      return reply.code(201).send(result);
    } catch (err) {
      if (err instanceof Error && err.message === 'IMPORT_PERMISSION_DENIED') {
        return reply.code(403).send({ error_code: 'IMPORT_PERMISSION_DENIED', message: "You don't have access to this document in the source system." });

      if (err instanceof Error && err.message === 'PLAN_NOT_FOUND') {
        return reply.code(404).send({ error_code: 'PLAN_NOT_FOUND', message: 'This plan no longer exists or you have access.' });
      }
      throw err;
    }
  },
);
```
