```tsx
export interface ImportDocumentModalProps {

  onClose: () => void;
  onImported: () => void; // caller refetches the Plan Repository list
}
```

1. **Search field**: a `TextField` (not `Combobox` — the browse results aren't a fixed short options list suited to `Combobox`'s ARIA combobox/listbox pattern; a plain search-then-list is simpler and matches F3 S3.6's "Modal or dedicated form" flexibility) bound to local `searchQuery` state, with a `useQuery` keyed `['document-browse', searchQuery]` calling `apiGet<DocumentSearchResult[]>(`/api/v1/integrations/documents/browse?query=${encodeURIComponent(searchQuery)}`)`. Debounce via a simple `setTimeout`-based debounce (200-300ms) OR fire on every keystroke if the result set is small enough that debouncing adds unnecessary complexity for this MVP-depth stub's 2-3-document catalog — document whichever you choose inline.

2. **Results list**: render each `DocumentSearchResult` (`{ external_document_id, name, source_system }`) as a selectable row (reuse `Table` with 2 columns — Name, Source — and `onRowClick` selecting that row, OR a simpler radio-button-styled list if `Table`'s row-click selection model doesn't fit a single-select-then-confirm flow as naturally; prefer `Table` for consistency with every other list in this codebase unless it's genuinely awkward here). Selecting a row sets `selectedDocId` state. **The list renders EXACTLY what the browse endpoint returned — no client-side filtering, no additional permission check in this component** (the server-side filtering in Plan 08-02's `browseDocuments()` is the ENTIRE enforcement mechanism; this component must not re-implement or second-guess it).

3. **Mode choice**: once a document is selected, show two `Button`s (or a `Select`/radio pair) for "Import copy" vs "Link live" — matching F3 S3.6's literal "choose Import copy vs Link live sync mode" wording. Prefer two distinct primary-styled buttons in the modal footer (e.g. `Button variant="secondary"` "Import copy" and `Button variant="primary"` "Link live", OR a single confirm button with a preceding mode `Select` — either satisfies the spec; document your choice).

4. **Submit**: on "Import copy" click, `apiPost(`/api/v1/integrations/documents/${selectedDocId}/import`, {})`; on "Link live" click, `apiPost(`/api/v1/integrations/documents/${selectedDocId}/link`, {})`. On success (`201`), call `onImported()` and `onClose()`. On `403 IMPORT_PERMISSION_DENIED` (should be structurally unreachable via the UI's own browse-filtered list, but the backend may still reject a race — e.g. the user's simulated access set changed between browse and import), render the EXACT FRD message `"You don't have access to this document in the source system."` as an `Alert tone="danger"` INSIDE the modal (never a toast, matching `ReviewPlanModal.tsx`'s established convention), and keep the modal open so the user sees why.

5. Reset all local state (`searchQuery`, `selectedDocId`, any error state) on `open` transitioning from false→true, matching `ReviewPlanModal.tsx`'s own `React.useEffect` reset-on-open pattern exactly.
