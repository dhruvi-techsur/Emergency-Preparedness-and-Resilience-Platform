  No live Intelligence Layer gateway exists in this sandbox (TechArch 2.2: "deployed as an independently-scalable service... own container/pod," out of this phase's infrastructure scope — document this inline exactly as Phase 4's own unexecuted 04-01-PLAN.md documents for its own stub). Implement a deterministic stub function `draftViaGateway(context: string, targetField: string): {draft_text: string; sources: Array<{source,time,confidence}>; confidence_label: 'High'|'Medium'|'Low'}`:
  - If `context.trim().length === 0`: return `{draft_text: "No source available for this draft. Review carefully before using it.", sources: [], confidence_label: 'Low'}` — this satisfies the DB's `chk_sources_or_flagged` CHECK (empty `sources` array requires the text to ILIKE '%no source%') and the FRD's exact `AIDRAFT_NO_SOURCE` flagged-200 behavior (NOT an error status — "200 (flagged)" per Y2-errors.md).
  - Otherwise: return `{draft_text: "Drafted summary (stub — no live AI gateway in this environment): " + context.slice(0, 300), sources: [{source: 'Reviewed notes', time: new Date().toISOString(), confidence: 'Medium'}], confidence_label: 'Medium'}`.
  `INSERT INTO ai_drafts (target_feature, target_field, draft_text, sources, confidence_label, requesting_user_id) VALUES ($1,$2,$3,$4,$5,$6) RETURNING id, draft_text, sources, confidence_label`. Return `200 AiDraftResponse` (per TechArch's exact shape) — include `error_code: 'AIDRAFT_NO_SOURCE'` in the body ONLY when the context was empty (the FRD's "200 (flagged)" case means the flag rides inside a 200 body, not a different HTTP status).

- `POST /api/v1/ai-drafts/{id}/approve` (`action='approve'`) — body `{approver_id: string, edited_text?: string}`.
  1. `403 APPROVAL_REQUIRES_NAMED_USER` with FRD's EXACT message **"AI drafts must be approved by a signed-in person."** (note: this is a DIFFERENT exact string from the ics_forms-approve 403 message in 06-01 — Y2-errors.md documents TWO distinct messages sharing the SAME error code for two different validation contexts; use THIS plan's own context's exact wording) if `approver_id` is missing/empty, OR doesn't match `req.epmpUser!.id` (same server-side re-verification pattern as 06-01's ics-forms approve — never trust a client-asserted approver_id alone).
  2. `UPDATE ai_drafts SET action='approve', approved_by=$1, approved_at=now(), edited_text=$2 WHERE id=$3 RETURNING id, approved_by, approved_at`.
  3. Return `200 {id, approved_by, approved_at}`.

- `POST /api/v1/ai-drafts/{id}/discard` (`action='discard'`) — `UPDATE ai_drafts SET action='discard' WHERE id=$1` (NEVER a DELETE — the FRD's own Outputs section requires "Approval audit entries... on the owning record's Timeline/audit trail" and discard is documented as leaving "an audit note only (no content retained)" — the row itself IS that audit note; a hard delete would violate this). Return `204`.
