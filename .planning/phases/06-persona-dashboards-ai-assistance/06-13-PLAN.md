<objective>
Close UAT gap ref 8 (cosmetic, 06-UAT.md): the Signal Triage Queue's Dismiss
confirmation Modal's multiline Reason `TextField` visually overflows the
Modal's own right edge. Direct measurement during UAT diagnosis found the
true root cause is NOT specific to this one Modal — it is a systemic,
app-wide CSS integration gap: the design system's `tokens.css` scopes its
`box-sizing: border-box` reset to elements carrying the literal class `.ep`
(`.ep, .ep * { box-sizing: border-box }`), and the design system's own test
harnesses always wrap every fixture in `<div className="ep">` to activate
this reset — but the real app's shell root
(`frontend/app/src/app-shell/AppShell.tsx`) only ever applies the unrelated
class `ep-shell`, never `.ep` itself. Every design-system component with a
declared width plus its own padding/border (not just this one Modal+TextField
pairing) therefore renders in default `content-box` mode throughout the real
app — `getComputedStyle` measurement during UAT diagnosis confirmed
`document.querySelectorAll('.ep').length === 0` in the running app, and both
`.ep-modal` and the Reason `textarea` reporting `boxSizing: "content-box"`.

Purpose: a one-class fix at the app/design-system integration boundary (the
SAME fix the design system's own test harnesses already apply, just never
carried into the real app's shell) resolves not just this one reported
overflow but the entire systemic class of Modal+multiline-TextField width
miscalculations the UAT diagnosis identified across the codebase
(RecipientGroups, MessageTemplates, ComposeNotification, SignalDetail,
ResourceRequestDetail, ReviewPlanModal, RecordAuthority all share the
identical missing-`.ep`-ancestor defect per the gap's own `root_cause` field).

Output: `AppShell.tsx`'s root element gains the `.ep` class (kept alongside
the existing `.ep-shell` layout class, which is unrelated and untouched), plus
a regression-sampling check added to `signal-triage.spec.ts` proving the
Dismiss Modal's Reason textarea now renders fully inside the Modal's bounding
box at both a narrow and a wide viewport — the exact defect reported.
</objective>

UAT gap ref 8's own `root_cause` field is the authority here, confirmed by
direct live DOM inspection during diagnosis: `tokens.css`'s base reset
(`frontend/design-system/tokens/tokens.css:352-356`) is

```css
.ep,
.ep * {
  box-sizing: border-box;
}

.ep {
  background: var(--bg);
  color: var(--ink);
  font-family: var(--font-sans);
}
```

— scoped exclusively to descendants of an element carrying the literal class
`ep`. The design system's own test harnesses (`withTheme()` helper and
similar fixtures across `frontend/design-system/test/*.test.tsx`) always wrap
every rendered fixture in `<div className="ep">` specifically to activate
this reset before asserting on any component's layout — confirming this is
the INTENDED integration contract, not an internal design-system detail
callers are meant to ignore. The real app's shell root in
`frontend/app/src/app-shell/AppShell.tsx` (the single outermost `<div>`
wrapping every page in the entire application, current line 201) uses only
`className="ep-shell"` — `ep-shell` is this app's OWN layout class (defined in
`AppShell.css`, unrelated to and not colliding with the design system's `ep`
reset selector) and has never carried the `ep` token-reset-activator class
alongside it.

In `frontend/app/src/app-shell/AppShell.tsx`, change the root element's
`className` (currently `<div className="ep-shell">`, line 201) to carry BOTH
classes, space-separated, exactly mirroring the design system's own test
harness convention:

```typescript
    <div className="ep ep-shell">
```

Do not touch `AppShell.css`'s own `.ep-shell` rule (layout: flex,
min-height:100vh, background — all independent of box-sizing and unaffected
by this change) or any design-system component's own CSS (`Modal.css`,
`TextField.css`, or any other `.ep-*` component stylesheet) — per the gap's
own diagnosis, every one of those files is "internally consistent, authored
assuming border-box is active." This single class addition is the entire fix:
it makes that assumption true app-wide for the first time, rather than only
inside the design system's isolated test fixtures.

```typescript
    // Gap closure 06-13 (UAT ref 8, cosmetic) regression guard: the
    // multiline Reason textarea must render fully inside the Modal's own
    // bounding box, not overflow its right edge (the exact reported defect
    // — root cause was AppShell.tsx missing the `.ep` box-sizing:border-box
    // reset class, fixed in this same plan's Task 1).
    const modalBox = await modal.boundingBox();
    const reasonField = modal.getByLabel('Reason', { exact: false });

    expect(modalBox).toBeTruthy();
    expect(reasonBox).toBeTruthy();
    if (modalBox && reasonBox) {
      expect(reasonBox.x).toBeGreaterThanOrEqual(modalBox.x);
      expect(reasonBox.x + reasonBox.width).toBeLessThanOrEqual(modalBox.x + modalBox.width + 1);
    }
```
