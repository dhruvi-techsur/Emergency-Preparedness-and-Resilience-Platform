<objective>
Fix the single confirmed UAT blocker carried over unaddressed from the prior round: `documentRoutes()`'s registration-time call to `recordDocumentHealth('online')` (document-adapter.ts:527-530) is the ONE unguarded, registration-time DB call anywhere in the entire backend/src tree. With `DATABASE_URL` unset — the exact DEPLOY-01 D4 cold-boot contract ("starts and stays up with only PORT set") — `recordDocumentHealth()`'s bare `query()` call throws `AggregateError [ECONNREFUSED]`, which propagates uncaught through the unawaited `app.register(integrationGatewayRoutes)` call in server.ts:61 and crashes the Fastify process with exit code 1 before `/healthz` can ever bind.

Every sibling adapter in this same file (cad-adapter.ts, eoc-cots-adapter.ts, facility-adapter.ts, hazard-feed-adapter.ts, hris-roster-adapter.ts, notification-provider-adapter.ts) only reaches its own `record*Health()` call from inside a function invoked by a scheduler that server.ts's `start()` already wraps in a "must never crash the server" try/catch. document-adapter.ts is the one outlier: it calls its health-record function directly and unconditionally at route-registration time, with zero error handling anywhere in that specific call chain. The fix is a single localized try/catch at the one unguarded call site — no changes to `recordDocumentHealth()` itself, `routes.ts`, or `server.ts` are needed, and none are made.

Purpose: Restore DEPLOY-01 compliance (shipped v1.0 Phase 1, regressed by this phase's 09-02-PLAN.md's F17 document adapter) — a cold container with only PORT set must come up and answer its health check, the same graceful-degradation posture this codebase already enforces everywhere else.
Output: `documentRoutes()`'s startup health-stamp call wrapped in a try/catch that logs a warning and swallows the error, matching the exact pattern every sibling adapter's call chain and every server.ts start() block already uses. A new/extended test in `facility-document-adapter.test.ts` proves `recordDocumentHealth`'s own failure (DB unreachable) can no longer propagate out of `documentRoutes()`'s registration body, and that the happy-path write is unaffected when the DB is reachable.
</objective>
