## Summary

All 13 plans in Phase 1 ship a `<threat_model>` STRIDE register (T-01-01 through T-01-30). Every declared mitigation was traced to its actual shipped implementation — not just plan intent — by reading the real logic at the cited file:line and, for the highest-risk claims (JWKS signature verification, fail-closed OPA, audit single-writer/immutability, immediate suspend-invalidation, sessionStorage-not-localStorage, scrypt-hashed one-time secrets, synchronous federation-grant revocation sync, non-root container, no committed production secrets), confirming the code does what the register claims rather than accepting the claim text. 30 threats were examined; 30 are genuinely mitigated/accepted/transferred as documented, 0 are false claims. One already-known, already-accepted gap (T-01-20, no outbound webhook fetch timeout) remains open by the plan's own design and is carried forward here as an accepted risk, not a new finding. The 01-REVIEW.md code-review gate (3 iterations, 0 blockers/0 warnings, B1/W1/W2/W-new-1 all verified fixed) is cited as corroborating evidence, not re-derived. No new HIGH/CRITICAL issue outside the existing register was found. **Ship.**

## Accepted risks

| ID | Risk | Why accepted | Owner |
|----|------|--------------|-------|
| T-01-20 | Webhook delivery worker's outbound `fetch()` to an admin-registered `callback_url` has no request timeout — a slow/malicious subscriber endpoint could stall delivery processing. | Explicitly documented as a known Phase 1 gap in `01-09-PLAN.md`'s threat register; `callback_url` is only ever admin-registered (not attacker-reachable without existing `admin,create` permission), bounding the practical severity. Flagged for a hardening pass (`AbortController`-based ~10s timeout) before production webhook traffic scales. | Integration-gateway module owner, pre-GA hardening backlog |
| T-01-02 | Keycloak realm-import ships a fixed dev test-user password (`devpass123`). | Confirmed reachable only inside the local docker-compose network; never used as, or capable of becoming, a production credential (production SSO is configured via the Admin Console against the agency's own IdP per `1700000000001_seed-roles.js`'s comment). | Dev-stack owner |
| T-01-23 | Dev-mode Vite proxy (`/api` → `localhost:8080`) has no auth layer beyond the backend's own `requirePermission` checks. | Dev-server-only configuration; irrelevant to the production deploy path (`backend/src/static.ts` serves the built SPA directly from the same origin as the API in that environment). | Frontend dev-tooling owner |
