Create `frontend/app/src/auth/oidc-config.ts`: `UserManager` config from `oidc-client-ts` — `authority: 'http://localhost:8081/realms/epmp'`, `client_id: 'epmp-app'`, `redirect_uri: window.location.origin + '/auth/callback'`, `response_type: 'code'`, `scope: 'openid profile email'`, PKCE enabled by default in `oidc-client-ts`. Export a singleton `userManager` and helper `signIn()`/`signOut()`.

Create `frontend/app/src/pages/SignInCallback.tsx`: handles the OIDC redirect callback — calls `userManager.signinRedirectCallback()`, extracts the raw `id_token`, `POST`s it to the backend's `/api/v1/auth/sso/callback`, receives `{session_token, user}`, stores `session_token` (in-memory React context + `sessionStorage` for refresh survival — not `localStorage`, to limit XSS persistence window), then redirects to `/` (or the user's prior intended route).

Create `frontend/app/src/pages/RoleUnresolved.tsx`: renders the FRD's exact `ROLE_UNRESOLVED` message ("Your account isn't assigned a role yet. Contact your administrator.") via an `Alert` (tone="danger") inside a minimal centered `Card` — this is the page shown instead of a blank/broken screen when `GET /api/v1/me` returns 403.

Create `frontend/app/src/auth/RouteGuard.tsx`: a wrapper component that, on mount, calls `GET /api/v1/me`; while pending, renders nothing but a `Skeleton`-based full-page loading state; on 401, redirects to `signIn()`; on 403 `ROLE_UNRESOLVED`, renders `RoleUnresolved`; on success, provides the resolved `user` via React context to its children (the `AppShell` and everything inside it).

Create `frontend/app/src/main.tsx`: sets `document.documentElement.dataset.theme = 'light'` synchronously before any render (flash-of-wrong-theme guard), mounts `BrowserRouter` wrapping `RouteGuard` wrapping routes: `/auth/callback` → `SignInCallback`, everything else → `AppShell` (built in Task 2).

## Trust Boundaries

| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-21 | Information disclosure | `frontend/app/src/pages/SignInCallback.tsx` session-token storage | mitigate | Session token stored in `sessionStorage` (cleared on tab close), never `localStorage` — limits the persistence window of a token exposed to an XSS payload, should one exist elsewhere in the app. |
| T-01-22 | Spoofing | `frontend/app/src/auth/oidc-config.ts` | mitigate | PKCE (`oidc-client-ts` default) prevents authorization-code interception/replay by a malicious party without the original code verifier — standard mitigation for public (non-confidential) SPA clients. |
| T-01-23 | Information disclosure | `frontend/app/src/lib/api-client.ts` | accept | Dev-mode Vite proxy (`/api` → `http://localhost:8080`) has no additional auth layer beyond the backend's own `requirePermission` checks; acceptable for local dev, not a production deployment concern since this file configures only the dev server. |
</threat_model>
