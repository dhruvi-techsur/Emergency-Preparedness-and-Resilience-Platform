<objective>
Build the `auth-org` backend module's session/SSO/RBAC/audit core: validates Keycloak-issued OIDC tokens, mints a short-lived EPMP session JWT carrying resolved role + jurisdiction scope, enforces RBAC via a per-request OPA policy check (fail-closed, never cached across revocation), and exposes the single append-only `AuditService.record()` writer every other module will call. This is F8's non-negotiable foundation: no other route in this phase is reachable without `requirePermission` from this module.

Purpose: F8's hard requirements (immediate session invalidation on suspend, audit-log single-writer, no-caching-window RBAC) and F0's session resolution (`GET /api/v1/me`) both terminate here. Every admin/platform-API endpoint built in Wave 3 imports `requirePermission` and `AuditService` from this plan.
Output: a working `auth-org` Fastify module mounted on `backend/src/server.ts`, OPA-backed RBAC middleware, audit writer, and the F0 session/theme/nav-config endpoints.
</objective>

Document at the top of the file: "This is the ONLY code path permitted to write to audit_log. No other module's repository layer may INSERT into this table directly — call `AuditService.record()`." This is a code-review convention backstopped by the append-only trigger from 01-01 (which blocks UPDATE/DELETE, not INSERT — multiple INSERT call-sites would still violate the single-writer *pattern* even though the trigger doesn't block them; the discipline here is what makes `01-components.md §2.4`'s invariant actually true).

Create `backend/src/modules/auth-org/rbac.ts`: a Fastify `preHandler` factory.
```typescript
import { checkPermission } from './opa-client';
import { verifySessionToken } from './session';
import { query } from '../../db/client';

export function requirePermission(feature: string, action: string) {
  return async (req, reply) => {
    const auth = req.headers.authorization;
    if (!auth?.startsWith('Bearer ')) return reply.code(401).send({ error_code: 'SESSION_EXPIRED', message: 'Your session has ended. Sign in again to continue.' });
    let claims;
    try { claims = await verifySessionToken(auth.slice(7)); }
    catch { return reply.code(401).send({ error_code: 'SESSION_EXPIRED', message: 'Your session has ended. Sign in again to continue.' }); }

    // Re-fetch user status fresh on EVERY request — this is what makes a suspension
    // take effect immediately rather than waiting for the 15-min token to expire.
    const rows = await query<{ status: string; role_id: string; jurisdiction_scope: string[] }>(
      `SELECT status, role_id, jurisdiction_scope FROM users WHERE id = $1`, [claims.sub]
    );
    const user = rows[0];
    if (!user || user.status !== 'Active') {
      return reply.code(401).send({ error_code: 'SESSION_EXPIRED', message: 'Your session has ended. Sign in again to continue.' });
    }

    const allowed = await checkPermission({ role_id: user.role_id, feature, action });
    if (!allowed) {
      return reply.code(403).send({ error_code: 'ROLE_UNRESOLVED', message: "Your account isn't assigned a role yet. Contact your administrator." });
    }
    req.epmpUser = { id: claims.sub, role_id: user.role_id, jurisdiction_scope: user.jurisdiction_scope };
  };
}
```
Declare the Fastify request-decoration type (`declare module 'fastify' { interface FastifyRequest { epmpUser?: {...} } }`) in this file so downstream modules get typed `req.epmpUser`.

Create `backend/src/modules/auth-org/sso.ts`: `async function handleSsoCallback(idToken: string): Promise<{session_token: string; user: object}>`.
1. Fetch `sso_config` (the single active row where `active=true`).
2. Validate `idToken` signature against Keycloak's JWKS (`createRemoteJWKSet(new URL(process.env.KEYCLOAK_ISSUER + '/protocol/openid-connect/certs'))`, `jose.jwtVerify`).
3. Extract claims using `sso_config.attribute_mapping` (`email_attr`, `name_attr`, `group_attr`) — e.g. `claims[attribute_mapping.email_attr]`.
4. Resolve local user by `idp_subject = claims.sub`; if not found, JIT-provision: map `claims[group_attr]` (array) through `sso_config.group_to_role_mapping` to a `role_id` (first match; if none matches, reject with `403 ROLE_UNRESOLVED`), `INSERT INTO users (email, name, role_id, jurisdiction_scope, idp_subject, last_login_at) VALUES (...) ON CONFLICT (email) DO UPDATE SET idp_subject = EXCLUDED.idp_subject, last_login_at = now() RETURNING *`.
5. On any assertion/validation failure, throw a typed error the route handler converts to `401 SSO_AUTH_FAILED`.
6. On success: `UPDATE users SET last_login_at = now() WHERE id = $1`, call `AuditService.record(user.id, 'login')`, `mintSessionToken(user)`, return `{session_token, user: {id,email,name,role:{...},jurisdiction_scope,theme_preference}}` matching the `User` TypeScript interface in `03a-api-auth-admin.md` exactly.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Spoofing | `backend/src/modules/auth-org/sso.ts::handleSsoCallback` | mitigate | ID token signature verified against Keycloak's JWKS via `jose.createRemoteJWKSet`/`jwtVerify` before any claim is trusted — a forged/unsigned token is rejected with `401 SSO_AUTH_FAILED` before reaching user resolution. |
| T-01-06 | Elevation of privilege | `backend/src/modules/auth-org/rbac.ts::requirePermission` | mitigate | `checkPermission` fails closed (returns `false`, denies with 403) on OPA unreachability or decision absence — no code path defaults to "allow" when the policy engine cannot be reached. |
| T-01-07 | Tampering | `backend/src/modules/auth-org/audit.ts` | mitigate | `AuditService.record` is the single documented INSERT call-site into `audit_log`; combined with 01-01's immutability trigger, no code path can retroactively alter a written entry. |
| T-01-08 | Elevation of privilege | `backend/src/modules/auth-org/rbac.ts` (suspended-user bypass) | mitigate | `requirePermission` re-queries `users.status` from the database on every request rather than trusting a cached/token-embedded role — a suspended user's still-valid-by-expiry session JWT is rejected on the very next request after suspension. |
</threat_model>
