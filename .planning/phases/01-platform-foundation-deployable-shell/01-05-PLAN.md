</objective>

<task type="auto">
  <name>Task 1: TextField, Select, Checkbox, Switch</name>
  <files>frontend/design-system/src/forms/TextField.tsx, frontend/design-system/src/forms/Select.tsx, frontend/design-system/src/forms/Checkbox.tsx, frontend/design-system/src/forms/Switch.tsx</files>
  <action>
Create `frontend/design-system/src/forms/TextField.tsx`: `label` (required), `value`/`onChange` (controlled) or `defaultValue`, optional `hint`, `error` (string — rendered below the field in `var(--danger-text)` with an `Icon name="alert" size="sm"`, and sets `aria-invalid="true"` + `aria-describedby` pointing at the error element id), `required` (renders a required marker and sets the native `required` attribute), `multiline` (renders `<textarea>` instead of `<input>`), plus pass-through native props (`type`, `placeholder`, `inputMode`). Height `36px` default, `44px` when `size="lg"`. Label always above the field (`<label htmlFor={generatedId}>`), connected via a generated stable id (React `useId`). Border `var(--border-strong)`; focus `outline: 2px solid var(--focus-ring); outline-offset: 2px`.

Create `frontend/design-system/src/forms/Select.tsx`: native `<select>` styled to match `TextField`'s chrome. `label` (required), `options: {value,label}[]` (required), `value`/`onChange`, optional `hint`, `error`, `required`. Same label/error/focus conventions as `TextField`.

Create `frontend/design-system/src/forms/Checkbox.tsx`: `label` (required — the label IS the clickable hit area, wrapping both the box and text in a single `<label>`), `checked`/`onChange` or `defaultChecked`, optional `disabled`, `size` (`'default'` 16px box, `'lg'` 24px box for touch). Brand fill (`var(--brand)`) with a `check` `Icon` when checked. Visible focus ring on the box itself when the (visually hidden but functional) native `<input type="checkbox">` has focus.

Create `frontend/design-system/src/forms/Switch.tsx`: `label` (required, states the setting itself e.g. "Dark theme" not "Turn on dark theme"), `checked`/`onChange` or `defaultChecked`. `role="switch"`, 36×20px, `aria-checked` reflecting state. Brand fill when on, `var(--bg-sunken)` track when off.

All four: focus-ring never suppressed (no `outline: none` anywhere in these files), labels always rendered as real text (never placeholder-as-label).
  </action>
  <verify>
cd frontend/design-system && npx tsc --noEmit
grep -rln "outline:\s*none\|outline:\s*0" src/forms/TextField.tsx src/forms/Select.tsx src/forms/Checkbox.tsx src/forms/Switch.tsx && echo "FAIL: suppressed focus outline found" || echo "FOCUS RING NEVER SUPPRESSED"
grep -c "htmlFor" src/forms/TextField.tsx src/forms/Select.tsx | grep -v ":0" && echo "LABELS PROPERLY ASSOCIATED"
  </verify>
  <done>All four components compile; none contains `outline: none`/`outline: 0`; `TextField`/`Select` associate their `<label>` via `htmlFor` to a generated id, never relying on placeholder text alone.</done>

<task type="auto">
  <name>Task 2: Combobox + DatePicker</name>
  <files>frontend/design-system/src/forms/Combobox.tsx, frontend/design-system/src/forms/DatePicker.tsx</files>
  <action>
Create `frontend/design-system/src/forms/Combobox.tsx`: ARIA `combobox` + `listbox` pattern (`role="combobox"` on the input, `aria-expanded`, `aria-controls` pointing at the listbox id, `aria-activedescendant` tracking the highlighted option). `label` (required), `options: {value,label,hint?,disabled?}[]`, `value`/`onChange(value, option)` or `defaultValue`, optional `hint`, `error`, `required`, `clearable` (renders an `x` `IconButton`-style clear affordance... note: this plan doesn't have `IconButton` imported from a different file path issue — import it from `'../actions/IconButton'`), `placeholder` (states what to type, e.g. "Search jurisdictions" — never substitutes for `label`), `size`. For server-backed search: `onSearch(query: string)`, `loading` (shows `Skeleton`-style option-row placeholders while true), caller passes pre-filtered `options` back in. Keyboard: typing filters the local `options` client-side when `onSearch` is absent; Up/Down moves `aria-activedescendant`; Enter selects the highlighted option and closes; Escape closes without selecting. `emptyText` prop (required when no default makes sense — default `"No matches. Try a different search."`, actionable per the "say what to do next" rule). Value is always the option's `value`, never raw free text.

Create `frontend/design-system/src/forms/DatePicker.tsx`: `label` (required), `value`/`onChange(isoString)` or `defaultValue`, optional `withTime` (adds a 24-hour time input, returned/accepted format `YYYY-MM-DDTHH:mm`), `zone` (shown in the hint text, e.g. "ET" — never silently defaulted, so when `withTime` is true and `zone` is absent, render a visible hint "Time zone not set" rather than guessing), `min`/`max` (ISO date bounds), `hint`, `error`, `required`, `size`. Typing a date directly into the text input always works (the calendar popover is an enhancement, not the only entry path — critical for keyboard/screen-reader/field use per the hard rule). Calendar popover: month grid, Arrow keys move by day/week, PageUp/PageDown change month, Escape closes and returns focus to the field, today has an outline ring, selected day gets `var(--brand)` fill, out-of-`min`/`max` days are dimmed and `tabIndex={-1}` (not focusable). Invalid/out-of-range typed input shows an `error` on blur stating what's allowed (e.g. "Enter a date on or after 2026-11-16").
  </action>
  <verify>

  </verify>
  <done>`Combobox` implements the ARIA combobox/listbox pattern with full keyboard support; `DatePicker` accepts typed ISO-format entry as a first-class path (not merely a calendar-click UI), with the calendar as a keyboard-operable enhancement.</done>
