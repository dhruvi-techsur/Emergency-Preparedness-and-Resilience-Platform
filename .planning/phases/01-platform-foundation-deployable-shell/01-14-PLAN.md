<objective>
Close UAT gap ref 3 ("there is no sign in option") to the extent this phase's own repository can close it. The UAT's own diagnosis (confidence: proven, independently re-verified in `.planning/debug/no-sign-in-option-reachable.md`) is explicit: the root cause is the ABSENCE of `.pivota/start-dev.sh` — a dev-server-startup-script generated by the platform's `init-dev-server` workflow, not by this phase's application code. `pivota-deploy.yaml` declares only port 8080 (the backend's port), which in native dev mode (`npm run dev`, no `vite build` run) has nothing in `frontend/app/dist` to serve, so `backend/src/static.ts` correctly (by its own documented design) answers every non-API GET with a bare JSON 404. The real app — Vite's dev server on 5173, with a working sign-in flow — is live and correct; a human was simply never routed to it.

**This plan does NOT claim to fully close gap ref 3.** The actual fix — generating `.pivota/start-dev.sh` so a preview session routes to 5173 in dev mode — is an `init-dev-server` platform-workflow concern outside this phase's repository scope, exactly as the UAT's `missing` field states. What IS fixable within this phase's own code, and what this plan does, is make the port split impossible to miss for any human (or future agent) who runs this repo's own `npm run dev` directly: a startup banner naming both URLs, and README documentation of the same split with the exact reason 8080 shows nothing.

Purpose: Reduce "invisible app" confusion to the maximum extent achievable from in-repo code, while being explicit (in this plan and its SUMMARY) that full closure requires the separate `init-dev-server` workflow to run for this project.
Output: `package.json`'s `dev` script prints a startup banner naming 5173 as the sign-in URL before docker compose/concurrently launch; `README.md` gains a "Development" section documenting the 5173/8080 split.
</objective>

UAT gap ref 3 (`.planning/phases/01-platform-foundation-deployable-shell/01-UAT.md` lines 88-103, `confidence: proven`): a human testing SSO sign-in reported "there is no sign in option." The diagnosed and independently re-verified root cause (see `.planning/debug/no-sign-in-option-reachable.md`'s full resolution) is that `.pivota/start-dev.sh` does not exist yet (first `init-dev-server` run for this project), so the only declared port a preview session can route to is `pivota-deploy.yaml`'s `port: 8080` — the backend's port, which in native dev mode has no `frontend/app/dist` to serve and returns a bare JSON 404. The real app with a working sign-in flow lives on port 5173.

**The actual fix is NOT in this phase's code** — it's the `init-dev-server` workflow generating `.pivota/start-dev.sh` with the correct dev-mode port declaration (5173, or an orchestration of both ports). That workflow is outside `plan-phase`'s and this phase's scope; do not attempt to write `.pivota/start-dev.sh` yourself (per `runtime-environment.md` §7a, only `init-dev-server` generates that file).

What this task DOES fix, in-repo:

1. In root `package.json`'s `"dev"` script, prepend an `echo` banner — before `docker compose up` runs — naming BOTH ports and which one is the sign-in UI, e.g.:
   ```json
   "dev": "echo '\\n=== EPMP dev mode ===\\nSign-in UI (open this):  http://localhost:5173\\nBackend API only:        http://localhost:8080  (no UI here until a production build exists)\\n======================\\n' && docker compose up -d db nats opa keycloak && npm run build -w frontend/design-system && concurrently -n design-system,backend,frontend -c magenta,blue,green \"npm run dev -w frontend/design-system\" \"npm run dev -w backend\" \"npm run dev -w frontend\""
   ```
   Keep every existing step of the script exactly as-is (docker compose up, design-system build, concurrently with its three named processes) — only prepend the banner. Do not change the dev script's ports, workspaces, or process list; this is additive per the Deployability Checklist's "the preview is untouched" rule — this is dev tooling, not deployment.

2. Add a `## Development` section to `README.md` documenting:
   - Running `npm run dev` from the repo root starts Postgres/NATS/OPA/Keycloak via docker compose, builds the design system, then runs backend + frontend dev servers concurrently.
   - **Open `http://localhost:5173`** — the Vite dev server, which serves the real SPA with the sign-in flow.
   - `http://localhost:8080` is the backend API only. In native dev mode it has no built frontend to serve (`frontend/app/dist` only exists after `npm run build -w frontend/app`), so every non-`/api` GET there returns a bare JSON 404 — this is expected, not a bug.
   - `pivota-deploy.yaml`'s `port: 8080` is the PRODUCTION/deployed port (where the Dockerfile's build stage has already run `vite build`, so `frontend/app/dist` exists and 8080 correctly serves the SPA) — it is not meant to be used directly in native dev mode.
