  <name>Task 1: Table (with loading/empty/error variants built in)</name>
  <files>frontend/design-system/src/data/Table.tsx</files>
  <action>
Create `frontend/design-system/src/data/Table.tsx`: `columns: {key: string; header: string; align?: 'left'|'right'; width?: string; render?: (row) => ReactNode}[]`, `rows: T[]`, `rowKey: (row: T) => string`, optional `selectedKey`, `onRowClick`, `compact`, `caption` (screen-reader-only `<caption>` element — required prop, since every table needs an accessible title even when visually implied by a surrounding `PageHeader`). Sticky `bg-subtle` header, 1px `var(--border)` row rules, hover row tint `var(--bg-subtle)`, `selectedKey` row gets `var(--brand-subtle)`. Numbers (columns where `align='right'`) use tabular figures (`font-variant-numeric: tabular-nums`).

**Mandatory state props** (not separate components — Table owns its own loading/empty/error presentation per F0's "every list/table/panel" requirement, so every consumer gets this for free rather than re-implementing it per screen):
- `loading?: boolean` — when true, ignores `rows` and renders 6 `Skeleton` rows sized to the column layout.
- `error?: {message: string; onRetry: () => void}` — when present (and not loading), renders a `danger` `Alert` with the message and a "Retry" action **above** the table, and still renders the last-known `rows` beneath it (per "keep last-known data visible, labeled with its age" — accept an optional `asOfLabel?: string` rendered as `caption` text near the Alert when both `error` and `rows` are present).
- `empty?: {title: string; children?: ReactNode; action?: ReactNode}` — when `rows.length === 0` and not `loading`/`error`, renders `EmptyState` in place of the table body (caller supplies distinct first-use vs. filtered-out copy via this prop, per the "differentiated empty copy" rule — Table doesn't guess which case it is).

A status column (any column whose `render` returns a value flagged via a `isStatus` metadata marker — simplest implementation: expose a `Table.StatusCell` helper component that internally renders `Badge`, and document in TSDoc that any column displaying a status MUST use `Table.StatusCell` in its `render`, never return a raw colored `<span>`) always goes through `Badge`.
  </action>

Create `frontend/design-system/src/overlays/Modal.tsx`: `open` (required), `title` (required — states the decision, e.g. "Suspend this user?"), `children` (body states the consequence), `footer` (Buttons — document the "primary last and rightmost" convention in TSDoc, same pattern as `PageHeader.actions`), `onClose` (required), optional `width` (default 480px max), `danger` (switches `role` from `dialog` to `alertdialog` and renders the primary footer button, if any, with `variant="danger"` implicitly expected from the caller — document that danger modals' primary action must be an outcome-named `Button variant="danger"`, e.g. "Suspend access" not "Yes").

Focus management (implement with a small internal `useEffect`, no external dependency needed): on `open` becoming true, store `document.activeElement` as the trigger, move focus to the modal's first focusable element (or the modal container itself if none); trap `Tab`/`Shift+Tab` within the modal's focusable elements (cycle, don't escape to the page behind the scrim); on `Escape` keydown, call `onClose`; on close (open becoming false, or unmount), restore focus to the stored trigger element. Scrim: `var(--bg-overlay)` covering the viewport, `z-index` above page content; the only large shadow in the system (`var(--shadow-lg)`), `var(--radius-xl)` corners. Never render two `Modal`s simultaneously open — document this as a caller contract (the library doesn't enforce a global singleton, since that would require module-level mutable state inappropriate for a component library, but TSDoc explicitly calls out "never stack modals" per the spec's anti-pattern list).
