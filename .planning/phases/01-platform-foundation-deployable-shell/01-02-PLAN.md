<objective>
Build the first slice of the EPMP Design System as a real, token-driven React component library exposing `window.EPMP` — since no prebuilt component bundle exists in the repo (only the PDF specification), this phase must build it to spec. This plan lays the build pipeline, the full token set across all three themes, and the foundational/feedback components every later screen in this phase depends on.

Purpose: F0 and every other feature requires building "exclusively from window.EPMP components and design tokens — no raw hex colors, no custom components." That object doesn't exist until this plan creates it.
Output: `frontend/design-system` workspace package with `tokens.css`/`tokens.json`, a Vite library build producing `dist/bundle.js` (attaches `window.EPMP`) + `dist/bundle.css`, and 8 foundational/feedback components.
</objective>

Create `frontend/design-system/tokens/tokens.css`: generated/hand-written CSS defining every token above as a custom property, scoped three ways:
```css
:root, [data-theme="light"] { --bg: #ffffff; --ink: #0f2b43; --brand: #0a7c84; /* ...all light-theme tokens... */ }
[data-theme="dark"] { --bg: #0a1722; --ink: #e8eef3; --brand: #4cc3cb; /* ...all dark-theme tokens... */ }
[data-theme="contrast"] { --bg: #ffffff; --ink: #00111f; --brand: #00505a; /* ...all contrast-theme tokens... */ }
```
Plus non-color tokens (spacing/radius/motion/breakpoints as CSS custom properties, theme-invariant, declared once on `:root`) and type classes `.h1`...`.display` (font-family `Lato, sans-serif`; `.code`/`.data` use `'IBM Plex Mono', monospace`) matching the exact px/line-height pairs above. Add `@media (prefers-reduced-motion: reduce) { * { animation: none !important; transition: none !important; } }` per the motion chapter's reduced-motion requirement.

Create `frontend/design-system/src/feedback/Badge.tsx`: `tone` (`'neutral'|'brand'|'info'|'success'|'warning'|'danger'`, default `'neutral'`), `children` (1-3 word text, required — Badge never renders icon/color alone), `icon` (defaults per tone: success→`check`, warning→`alert`, danger→`danger`, info→`info`; pass `false` to suppress, `neutral`/`brand` have no default icon), `solid` (reserved for danger/warning needing top priority — switches ground from `*-subtle` to `*-solid` with `on-*` text). Renders icon (`size="sm"`, `aria-hidden`) + the word together — this component can never be instantiated icon-only or color-only, enforcing F0's "status always icon + word + color" hard rule structurally.

Create `frontend/design-system/src/feedback/Alert.tsx`: `tone` (`'info'|'success'|'warning'|'danger'|'neutral'`), `title` (required, short outcome), `children` (1-2 sentences), `actions` (array of `Button` elements, e.g. Retry), `onDismiss` (optional — when provided and tone is `info`/`success`, renders a dismiss `IconButton`; when tone is `danger`/`warning`, `onDismiss` is ignored and `role="alert"` is set, matching "persist errors/warnings until resolved" rule). Ground uses `var(--{tone}-subtle)`, border `var(--{tone}-border)`, icon+text `var(--{tone}-text)`.

Create `frontend/design-system/src/feedback/EmptyState.tsx`: `title` (required), `icon` (optional, rendered in a 48px disc of `var(--bg-sunken)`), `children` (explains why + what's next), `action` (a single `Button`, optional). No illustrations. Distinguishing first-use vs. filtered-out vs. error is the **caller's** responsibility (different `title`/`children`/`action` per case) — this component itself is state-agnostic by design, matching the spec's "each gets different copy" guidance.

Create `frontend/design-system/src/feedback/Toast.tsx`: `children` (one sentence, past tense), `tone` (optional), `title` (optional), `action` (a `ghost` `Button`, usually "Undo"), `onDismiss`. Surface `var(--bg-inverse)`/`var(--ink-inverse)`. Auto-dismiss after 6000ms unless `tone="danger"` (persists until manually dismissed) — implement via an internal `useEffect` timer, not a prop the caller must remember to set.
