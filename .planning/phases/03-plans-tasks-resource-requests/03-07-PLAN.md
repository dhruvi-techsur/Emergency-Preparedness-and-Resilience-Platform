<objective>
Extend Phase 1's idempotent seed script with `role_permissions` rows for the three NEW feature-permission strings this phase introduces (`plans`, `tasks`, `resource_requests`), granting them to the FRD-named roles the phase's various backend plans (03-01, 03-03, 03-04) already assumed would exist by the time their routes are actually exercised. This plan exists because 03-01/03-03/03-04 each explicitly deferred "which roles get this permission" to this plan, following the exact same split Phase 2's `02-01` established between schema/routes (which only need SOME role_permissions row to exist for RBAC gating to function) and the actual role-to-permission grants (seed data).

Purpose: Without this plan, every route built in 03-01/03-03/03-04 is correctly gated by `requirePermission` but UNREACHABLE by any seeded user — the backend Playwright/integration tests in those plans seed their OWN test-scoped role_permissions rows directly via `query()` (bypassing this script, as 02-01's own tests did), so those plans' tests pass without this plan existing. But the FRONTEND Playwright tests in 03-05/03-06/03-08 sign in as REAL seeded users and need the real seed script to grant these permissions for the SideNav items and actions to appear at all — this plan is the dependency those frontend plans implicitly need, made explicit and built once rather than duplicated per-plan.
Output: `seed.ts` extended with three new idempotent `role_permissions` grant blocks, following 02-01's exact pattern.
</objective>
