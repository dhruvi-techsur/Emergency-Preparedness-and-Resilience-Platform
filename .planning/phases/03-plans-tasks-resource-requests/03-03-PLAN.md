<objective>
Build the `plans` backend module from scratch (no Phase-1/Phase-2 prior art — this is a NEW module per TechArch's `01-components.md` module boundary list): the Draft → Review → Approved state machine with immutable, append-only version history and a server-enforced no-self-approval rule (backstopped by both an application-layer check AND a database CHECK constraint, matching the defense-in-depth pattern Phase 2 used for the Timeline's append-only trigger), plan-section CRUD, and the section-to-task-template linkage that makes success criterion 2's "linked template offered for one-click task creation" possible.

Purpose: Success criterion 1 (Draft→Review→Approved with immutable history and no self-approval) and the linkage half of criterion 2 (linking a plan section to a task template) are entirely this plan's responsibility. The OTHER half of criterion 2 — materializing a linked template into a real task when an incident references the plan — is this plan's `POST /api/v1/plans/{id}/materialize-tasks` endpoint (added in Task 3), which calls 03-01's `TaskService.createFromTemplate` per TechArch's explicit cross-module rule ("plans emits the template list; incident-ops performs the actual task creation").
Output: A new `plans` Fastify module mounted on `backend/src/server.ts` alongside the existing `auth-org`/`incident-ops`/`integration-gateway` modules, migrated schema, and the full Draft→Review→Approved→link-tasks→materialize API surface.

Sequencing note: this plan depends on `03-02` (in addition to `03-01`) not because `plans`' routes need anything `overdue-sweep.ts` produces at runtime — the materialize-tasks endpoint calls `TaskService.createFromTemplate` from 03-01 directly, with no dependency on the sweep — but because both plans edit the SAME shared file, `backend/src/server.ts` (03-02 adds `startOverdueSweepScheduler()`; this plan adds `fastify.register(planRoutes)`). Running them in the same wave risks a lost-update race on that file, the exact defect class Phase 2's first draft hit twice. Task 3 below appends this plan's route registration to the file 03-02 leaves behind, rather than assuming a from-03-01-only starting point.
</objective>

```sql
CREATE TABLE plans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(200) NOT NULL CHECK (char_length(name) BETWEEN 3 AND 200),
  type VARCHAR(20) NOT NULL CHECK (type IN ('EOP','SOP','Annex')),
  jurisdiction_id UUID NOT NULL REFERENCES jurisdictions(id),
  status VARCHAR(20) NOT NULL DEFAULT 'Draft' CHECK (status IN ('Draft','Review','Approved')),
  current_version INTEGER NOT NULL DEFAULT 1,
  source_document_ref TEXT,
  owner_id UUID NOT NULL REFERENCES users(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
ALTER TABLE plans ENABLE ROW LEVEL SECURITY;

CREATE TABLE plan_versions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  plan_id UUID NOT NULL REFERENCES plans(id),
  version_number INTEGER NOT NULL,
  content_snapshot JSONB NOT NULL,
  submitted_by UUID REFERENCES users(id),
  reviewed_by UUID REFERENCES users(id),
  review_action VARCHAR(20) CHECK (review_action IN ('approve','request_changes')),
  reviewed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (plan_id, version_number),
  CONSTRAINT chk_no_self_approval CHECK (reviewed_by IS NULL OR submitted_by IS NULL OR reviewed_by != submitted_by)
);

CREATE TABLE plan_sections (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  plan_id UUID NOT NULL REFERENCES plans(id),
  heading VARCHAR(300) NOT NULL,
  body TEXT,
  sort_order INTEGER NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE plan_task_templates (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  plan_section_id UUID NOT NULL REFERENCES plan_sections(id),
  default_title VARCHAR(200) NOT NULL,
  default_owner_role VARCHAR(100),
  default_due_offset_minutes INTEGER,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE document_links (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  plan_id UUID REFERENCES plans(id),
  external_document_id VARCHAR(300) NOT NULL,
  source_system VARCHAR(100) NOT NULL,
  mode VARCHAR(20) NOT NULL CHECK (mode IN ('import_copy','link_live')),
  imported_by UUID NOT NULL REFERENCES users(id),
  last_permission_check_at TIMESTAMPTZ,
  permission_status VARCHAR(20) NOT NULL DEFAULT 'valid' CHECK (permission_status IN ('valid','revoked')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_plans_jurisdiction_status ON plans(jurisdiction_id, status);
CREATE INDEX idx_plan_versions_plan ON plan_versions(plan_id, version_number DESC);
CREATE INDEX idx_plan_sections_plan ON plan_sections(plan_id, sort_order);
CREATE INDEX idx_plan_task_templates_section ON plan_task_templates(plan_section_id);
CREATE INDEX idx_document_links_plan ON document_links(plan_id);
```
