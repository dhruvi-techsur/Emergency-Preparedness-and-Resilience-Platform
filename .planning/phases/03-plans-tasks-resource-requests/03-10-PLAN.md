verbatim — do not abstract):

```
POST /api/v1/plans/{id}/materialize-tasks
Request: { incident_id: string; section_ids?: string[] }
Response (200): { created: Array<{id, title, status}>, skipped: Array<{template_id, reason}> }
Response (404): PLAN_NOT_FOUND | RECORD_NOT_FOUND (bad incident_id / out of jurisdiction scope)
Response (409): { error_code: 'INVALID_STATUS_TRANSITION', message: '...' } (plan not Approved — should
  never reach this call since the button is gated, but the modal must still
  render this as a visible Alert, not swallow it)
```

Component props:

```ts
  onClose: () => void;
}
```

Behavior:
- Only render section checkboxes for sections where
  `linked_task_templates.length > 0` (sections with zero templates have
  nothing to materialize — mirrors `materialize.ts`'s own
  `section_ids` filter, which joins through `plan_task_templates`).
- Default: no section filter applied (all eligible sections' templates
  materialize) — section checkboxes are an opt-in NARROWING filter, not a
  required selection. This matches the FRD's "offered... rather than
  requiring tasks to be written from scratch" framing: the default
  one-click path is "pick an incident, click Materialize", not forcing a
  per-section decision first.
- An incident `Combobox` (required) — same options-source pattern as
  `CreateTask.tsx`'s incident field (`GET /api/v1/incidents?page_size=1000`).
- Footer: "Cancel" (ghost) / "Materialize tasks" (primary, `loading`
  while submitting, `disabled` until an incident is selected).
- On submit: `apiPost(`/api/v1/plans/${planId}/materialize-tasks`, { incident_id, ...(selectedSectionIds.length > 0 ? { section_ids: selectedSectionIds } : {}) })`.
- On success: render the result INSIDE the modal (don't just close it) —
  a list of created task titles (tone: success Alert, e.g. "3 tasks
  created") and, if `skipped.length > 0`, a second warning Alert listing
  skipped template ids + reasons (e.g. "1 template skipped: no user holds
  the role 'planning_logistics_chief'" — reason codes are
  `NO_USER_FOR_ROLE`; render a human string per code, don't show the raw
  code). Footer changes to a single "Done" button that calls `onClose()`.
- On error: render `err.message` (via `ApiRequestError`) in a danger
  `Alert`, same pattern `LinkTasksModal.tsx` already uses for its own
  error state — including the 409 `INVALID_STATUS_TRANSITION` case,
  rendered verbatim (don't special-case it; the generic error Alert
  already covers it).
- Reset all local state (`incidentId`, `selectedSectionIds`, `result`,
  `error`) on `open` transitioning true, mirroring `LinkTasksModal.tsx`'s
  own `React.useEffect(() => { if (open) {...} }, [open, ...])` reset
  pattern.
