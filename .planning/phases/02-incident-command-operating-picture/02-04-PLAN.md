<objective>
Build the design system's MAPS component family (`MapCanvas`, `MapControls`, `MapLegend`, `MapPopup`, `LayerPanel`) plus the `Provenance` product-pattern chip every map/data-source surface attaches to. Since no prebuilt map engine integration exists, `MapCanvas` renders markers via percentage-based `x`/`y` positioning per the design system's own documented "map your projection to these or replace with your engine's overlay" contract — this is the spec's intended abstraction, not a shortcut.

Purpose: Success criteria 4 and 5 ("renders...status-coded, shape-distinguished markers on a real GIS-sourced base map"; "falls back to a schematic base map... the page never fails to render") are entirely UI-rendering concerns this plan owns. Without these components, the backend's `operating-picture` endpoint (02-03) has nothing to render into.
Output: 6 components added to `window.EPMP`, completing the component inventory the Phase 2 operating-picture page (02-07/02-08) needs.
</objective>

  <action>
Create `frontend/design-system/src/maps/MapCanvas.tsx`: per the spec's exact contract — `height` (required), `markers` as `{id,x,y,type:'incident'|'facility'|'resource'|'shelter',tone,label,status}[]` with `x`,`y` 0-100 (percent of canvas), `areas` as `{id,points,tone,label}[]` (optional), `lines` as `{id,points,kind,dashed}[]` (optional), `selectedId`, `onSelect(id)`, slots `topLeft`/`topRight`/`bottomLeft`/`popup` (ReactNode), `status` (string, rendered bottom as the status bar), `attribution` (optional string), `offline` (boolean — when true, renders a visibly schematic/hatched base fill instead of a real tile/vector base and shows a `Badge` or label reading exactly `"Schematic base map, offline"`), `label` (optional title), `basemap` (default `true`; `false` renders a transparent background for overlaying a real map engine underneath per the spec's integration note).

Marker rendering: shape by `type` (incident→diamond via a rotated square `<div>` or inline SVG path, facility→square, resource→triangle, shelter→circle), fill by `tone`→the matching status color token (`var(--danger-solid)` etc.), outline always `2px solid var(--ink)` for 3:1 contrast on any base per the spec's hard rule. Selected marker (`id === selectedId`) gets a `var(--focus-ring)` halo (box-shadow ring, not a border swap, so it layers over the existing outline). Every marker is a real focusable element (`tabIndex={0}`, `role="button"`, `aria-label={label + ' — ' + status}`) responding to `Enter`/`Space` by calling `onSelect(id)`. Beneath the visual markers, render a visually-hidden (`position:absolute; width:1px; height:1px; overflow:hidden; clip:rect(0,0,0,0)` — NOT `display:none`, which would remove it from the accessibility tree) `<ul>` listing every marker's `label`+`status` as plain text, giving screen-reader users the same information set as the visual map.

Base styling (non-offline): flat background using `var(--map-land)`, with the `status`/`attribution` strings rendered in a bottom status-bar strip. Offline styling: a diagonal-hatch or dotted pattern background (CSS `repeating-linear-gradient` using `var(--map-land)`/`var(--bg-sunken)`, no raw hex) plus a visible `Badge tone="warning"` (or plain labeled text, since `Badge` isn't yet imported into this file's dependency chain — simplest: a styled `<div>` reading the exact string) positioned `topLeft` unless the caller's own `topLeft` slot is occupied, in which case render it adjacent, never dropped. **Critical: `offline` affects ONLY the base-layer rendering — markers/areas/lines from props always render identically regardless of `offline`'s value.** Document this in a TSDoc comment directly above the component, since this is the literal mechanism satisfying "the page never fails to render."

Create `frontend/design-system/src/maps/MapControls.tsx`: `onZoomIn`, `onZoomOut` (required, always shown); optional `onLocate`, `onLayers` (with `layersOpen: boolean`), `onFullscreen` — each renders an `IconButton` (36px) ONLY when its handler prop is provided (undefined handler ⇒ button not rendered, per the spec's "buttons without a handler are not shown"). Vertical stack in one `var(--border-strong)`-bordered group, meant to be placed in `MapCanvas`'s `topRight` slot by the consumer.
  </action>

When `verified` is `false` (or explicitly `undefined` treated as unverified-by-default is WRONG per spec — default is `true`; only an explicit `false` triggers this): renders with a **dashed** outline (`border-style: dashed`), an `Icon name="alert" size="sm"` (not `aria-hidden`, since it's meaningful here — use `label="Unverified"` so it's announced), and the literal word `"Unverified"` appended after the source text. This structural branch — dashed+icon+word, never just a color change — is the mechanism satisfying "never turn an unverified feed into a plain operational fact."

Create `frontend/design-system/src/maps/MapLegend.tsx`: `items` as `{kind:'marker'|'area'|'line'|'boundary', type?:string, tone?:string, dashed?:boolean, label:string}[]` (required), optional `title`.
