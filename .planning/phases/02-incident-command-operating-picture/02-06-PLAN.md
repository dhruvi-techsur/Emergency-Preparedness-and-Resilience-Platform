<objective>
Build the Incident Workspace (S1.3) — the page every command-staff interaction centers on — with its pinned command-role panel, fixed Timeline/Tasks/Resources/Reports tab order, and the two modals that gate its most consequential actions: Command Role Assignment (S1.4) and Activation Level Change (S1.5, danger-tier on escalation).

Purpose: Success criteria 2 and 3 become observable to a real user through this plan — 02-02's backend gates (commander-required, confirmation-required) exist, but nothing renders their consequences to a human until this plan's Modals exist.
Output: Three composed screens/modals, routed at `/incidents/:id`, reachable from the Incident List's row-click (02-05).

Sequencing note: this plan depends on `02-05` (in addition to `02-01`/`02-02`) not because `IncidentWorkspace` needs anything `IncidentList`/`CreateIncident` produce at runtime — the workspace is reachable by direct URL and by row-click alike — but because both plans edit the SAME shared file, `frontend/app/src/app-shell/AppShell.tsx` (02-05 adds `/incidents` and `/incidents/new`; this plan adds `/incidents/:id`). Running them in the same wave risks a lost-update race on that file. Task 3 below appends this plan's route registration to the file `02-05` leaves behind, rather than assuming a from-01-10-only starting point.
</objective>
