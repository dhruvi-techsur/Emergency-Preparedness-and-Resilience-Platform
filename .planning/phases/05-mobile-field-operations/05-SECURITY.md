## Resolved findings

### F-05-01: field_reports and sync_conflicts had no jurisdiction-scope enforcement — a user could read and resolve another jurisdiction's field reports and conflicts
- **Status:** Fixed — re-confirmed fixed and non-regressed as of this 2026-11-19 re-audit (second re-verification same day, this time specifically to confirm 05-06's execution did not touch or regress it).
- **Prior finding:** Every route in `field-reports.ts` (photo GET, photo POST) and `sync-conflicts.ts` (list, single-get, resolve) was gated only by `requirePermission('field_reports', <action>)`, a feature-level check with no jurisdiction concept. A user whose `jurisdiction_scope` covered only Jurisdiction A could read/resolve Jurisdiction B's field reports/conflicts — a cross-jurisdiction IDOR.
- **Fix applied:** `field-reports.ts:342-343` (photo POST), `field-reports.ts:401-402` (photo GET), `sync-conflicts.ts:78-79` (list), `sync-conflicts.ts:133-134` (single-get), `sync-conflicts.ts:171-172` (resolve) — all 5 named routes join to `incidents` and filter on `(incident_id IS NULL OR i.jurisdiction_id = ANY($N))`, returning 404 (never 403) for an out-of-scope id.
- **Verification (this audit, 2026-11-19, re-run specifically to confirm no 05-06 drift):**
  - `git diff 59b85d4..HEAD --stat -- backend frontend` confirms `field-reports.ts`/`sync-conflicts.ts` are absent from 05-06's diff — these files could not have been touched by the plan under audit.
  - Both files re-read in full this session; the join+filter pattern at the 5 cited line ranges is present, byte-identical to the prior audit's citation.
  - `cd backend && npx vitest run src/modules/incident-ops/field-reports.test.ts` run live: **16/16 pass** (including the 9-test `F-05-01: jurisdiction-scope enforcement` describe block).
  - Full backend suite run live: **87/87 pass, 15 files, 0 failures** (86 pre-05-06 + 1 new 05-06 regression test — confirms zero regression anywhere, including in F-05-01's own coverage).
