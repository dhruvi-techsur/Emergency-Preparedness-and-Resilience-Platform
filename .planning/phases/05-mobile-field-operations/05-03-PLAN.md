<objective>
Build the three primary field-mobile screens a responder uses most: Field Home (landing/entry point), My Tasks (one-tap status updates), and Report Observation (the structured, offline-first, photo+location-capture form). These are the phase's success-criterion-1 screens — install, complete forms with one-tap capture, 44px targets, no hover/gesture-only interaction — and the first two screens to exercise the offline-queue built in 05-02 for real writes.

Purpose: This is where the offline-first guarantee becomes visible to a user — every submit/status-update on these screens goes through `enqueueFieldReport`/the queue, never a direct network call, so the phase's "every edit remains possible while offline" success criterion is actually true on the screens responders spend the most time on.
Output: 3 field-mobile pages plus a shared `FieldMobileShell` wrapper (pinning `SyncStatus`, used by this plan's screens AND 05-04's), with a Playwright test proving the offline-submit-then-queued-count-increments flow end-to-end against the real dev server, signing in as 05-05's real seeded field-responder identity.
</objective>
