  <action>
Create `frontend/design-system/src/feedback/Progress.tsx` per the spec's exact contract (EPMP-Design-System.pdf.md "Progress FEEDBACK" section): an 8px pill-shaped determinate progress bar.

```typescript
export type ProgressTone = 'brand' | 'success' | 'warning' | 'danger';

export interface ProgressProps {
  /** 0 to 100. Required. */
  value: number;
  /** e.g. "Step 1 of 4: Audience" or "68% acknowledged, 412 of 606". */
  label?: React.ReactNode;
  /** When true, prints the numeric percentage beside the bar — ALWAYS true
   * when the bar represents a measure (not decoration), per the spec's
   * "always show the number when the bar is a measure" rule. Default true. */
  showValue?: boolean;
  tone?: ProgressTone;
}
```

Render: a `role="progressbar"` div with `aria-valuenow={value}` `aria-valuemin={0}` `aria-valuemax={100}` `aria-label` (derived from `label` if a string, else a generic "Progress" fallback — document inline this is the accessible name), an 8px pill-radius track (`bg-subtle`) with a filled bar (`toneVar(tone)` style, same `var(--${tone}-solid, var(--brand))` helper pattern `MapCanvas.tsx` already established — reuse the exact same inline helper, do not invent a new one), width `${value}%`. If `label` provided, render it as text above/beside the bar. If `showValue` (default `true`), render `${value}%` as visible text — NEVER rely on bar width alone, per the spec's literal "Always show the number when the bar is a measure, not decoration" rule; this is why `showValue` defaults `true` rather than `false`.

Write `Progress.css` following the exact pill/track/fill visual spec: 8px height, fully-rounded (`border-radius: 999px`), track `background: var(--bg-subtle)`, fill `background: var(--brand-solid)` (overridden by `tone`), smooth `transition: width 200ms ease` (respecting `prefers-reduced-motion: reduce` — disable the transition, same convention `Skeleton.css`'s pulse-stopping rule already established for reduced motion).
  </action>

Create `frontend/design-system/src/data/LineChart.tsx` per the spec's exact contract ("Trends over time... up to 6 series. Series get color from viz-1..viz-6, a different marker shape each... hover or Left/Right arrows show an exact readout; a legend shows each series' latest value; a hidden data table repeats the data"):

```typescript
export interface LineChartSeries { name: string; values: (number | null)[]; dashed?: boolean; }
export interface LineChartThreshold { value: number; label: string; }
export interface LineChartProps {
  /** Accessible name — what the chart shows. Required. */
  label: string;
  series: LineChartSeries[]; // max 6, document inline as a caller contract
  xLabels: string[];
  title?: string;
  subtitle?: string;
  format?: (v: number) => string;
  yMin?: number;
  yMax?: number;
  height?: number;
  thresholds?: LineChartThreshold[];
  xName?: string;
}
```

Render an SVG line chart: each series plotted as a `<polyline>` with `stroke: var(--viz-N)` (N cycling 1-6 by series index), EACH series getting a distinct marker shape at every data point — circle (series 1), square (2), triangle (3), diamond (4), cross (5), and back to circle with a secondary visual distinguisher for series 6 (document inline the 6th-series fallback choice, since the spec names exactly 5 shapes for "up to 6 series" — Claude's discretion, document the resolution). `dashed` series render `stroke-dasharray`. `thresholds` render as horizontal dashed lines with a text label, never a color band (per spec's explicit "not a color band" rule). Y axis starts at 0 unless `yMin` is provided. A legend below/beside the chart lists each series' name + its LATEST value. Keyboard: Left/Right arrow keys (when the chart `<svg>` is focused) move a "current index" state showing an exact-value tooltip/readout for that x position across all series — implement via a visually-rendered `<text>` readout, not a native browser tooltip. Below the visual chart, render a visually-hidden (`ep-visually-hidden`, same class `MapCanvas.tsx` already uses) `<table>` with `xLabels` as columns and each series as a row, repeating the EXACT same data for screen readers.

Create `frontend/design-system/src/data/BarChart.tsx` per the spec's exact contract ("Compare quantities across categories: vertical or horizontal... grouped or stacked. Bars are 2px-rounded, values are printed on or beside the bar, stacked segments separated by a bg gap, patterns adds stripe/dot/hatch fills... a hidden data table repeats the data"):

```typescript
export interface BarChartSeries { name: string; values: number[]; }
export interface BarChartProps {
  label: string;
  categories: string[];
  series: BarChartSeries[];
  title?: string;
  subtitle?: string;
  stacked?: boolean;
  horizontal?: boolean;
  patterns?: boolean;
  format?: (v: number) => string;
  yMax?: number;
  height?: number;
  labelWidth?: number;
  xName?: string;
}
```

Render bars with 2px corner radius, `fill: var(--viz-N)` per series, the VALUE printed on/beside each bar (never axis-only readout — per spec's "print the values; do not make people read them off the axis" rule). `stacked` renders segments vertically combined with a `bg`-colored 1-2px gap between segments. `patterns` (when true) applies an SVG `<pattern>` fill (stripe/dot/hatch, cycling per series) UNDERNEATH the solid color fill — document inline this satisfies "series survive print and grayscale." A hidden data table (same `ep-visually-hidden` pattern) repeats categories × series values.

Create `frontend/design-system/src/data/DonutChart.tsx` per the spec's exact contract ("Part-to-whole for 2 to 5 segments, with a center total, a list legend with values and percentages, and a hidden data table... only for parts that add to a meaningful whole, never for trends or more than 5 segments"):

```typescript
export interface DonutSegment { label: string; value: number; tone?: 'success' | 'warning' | 'danger' | 'info'; }
export interface DonutChartProps {
  label: string;
  segments: DonutSegment[]; // 2-5, document inline as a caller contract — log a console.warn in dev if violated, never silently truncate
  center?: { value: string | number; label: string };
  title?: string;
  subtitle?: string;
  format?: (v: number) => string;
  size?: number;
}
```

Render an SVG ring built from `<circle>` `stroke-dasharray` segments (or `<path>` arcs — Claude's discretion on exact SVG technique within budget), each segment's color from `viz-N` UNLESS `tone` is set (then `var(--${tone}-solid)`, reusing the same tone-to-CSS-var helper pattern). Segments separated by a visible gap (not an outline color difference, per spec's "separation is a gap, not outline color" rule). `center` renders the total/label inside the ring's hole. Below/beside the ring, a LIST legend shows every segment's label, value, AND computed percentage as text — per spec's explicit "values and percentages are always listed; the ring alone is never the only carrier of information" rule, this list is NOT optional/hidden, it's always visibly rendered alongside the ring. A SEPARATE visually-hidden data table (same `ep-visually-hidden` pattern as the other two charts) also repeats the data for the screen-reader-table convention all three chart components share. If `segments.length > 5`, `console.warn` in development (checked via `process.env.NODE_ENV !== 'production'`) stating "DonutChart: segments.length exceeds the spec's 5-segment maximum; use BarChart for >5 categories" — still render all segments rather than silently dropping any (a caller-contract violation should be loud, not data-lossy).

Add all 4 new components' named exports (`Progress`, `LineChart`, `BarChart`, `DonutChart`) plus their prop/type exports to `frontend/design-system/src/index.ts`, in the FEEDBACK section (Progress, alongside Skeleton/Badge/Alert/EmptyState/Toast) and a NEW "DATA VISUALIZATION" section (LineChart/BarChart/DonutChart) respectively.
